# WP230〜280のL0事前生成参照（2026-09-08）

現在のSubmitへ、生成済みL0参照の読み込みを実装した。対象はWP230〜280で、従来経路との接続のためCSVにはWP220〜290を収録している。通常のL0追従と空間Hybridは同じ横位置目標を使う。設定は有効。

**WP230〜255のL0進入禁止は維持している。幾何学的に通れる参照を作ることと、現在のMPCがその姿勢から解を出せることは別であり、この区間の禁止を外せるという結果にはなっていない。**

検証車体幅はMPCの1.6m。車体長2.064m、原点が車体中心／後輪軸のどちらでも含むよう、原点から前後[-1.032, +1.554]mを検査する。これは事前生成の検証範囲であり、既存の衝突矩形設定や原点補正は変更していない。

既存Center CSVの法線上でL0参照の横位置を最適化し、L0内への収まり・曲率・操舵速度・車体壁余裕を制約にした。前後3点は従来中点と一致させ、接続位置を固定する。WP間は三次スプラインで再構成し、5cm以下の間隔で曲率と車体を再検査する。壁はCSVにある壁点と現行コードが再構成する壁点の両方を使い、占有地図でも車体内部を検査する。壁の突起を平滑化して消す処理はない。

`env/centerline/boundary.csv`は今回の軌道と座標範囲が合わないため検査元にしない。現在使用する`waypoint_bounds_center_mincurv_capped.csv`と`env/min_curv/occupancy_grid_map.pgm`を使う。

## MPCへの接続と優先順位

- 起動時にCenterのReferencePathだけへ参照を読み込む。CSV、Center経路、境界、地図のハッシュと設計寸法・設定を照合する。不一致ならエラーログを出して従来参照を使う。
- `_compute_lane_center()`から生成済み横位置を返す。空間Hybridもこの関数から移行先を取得するため、移行先と完了後の目標が揃う。
- 横位置の既存優先順位を解決した後、L0に関係する場合だけ向きの目的参照を追加する。Hybrid中は完了したL0の向きではなく、実際に混合した横位置列から向きを求める。
- 向きは既存Center向き目標へ25%反映し、WP220〜230、280〜290では五次曲線で従来参照へ接続する。**向きを100%追従する実装ではない**。現在の大きいyaw重みと入力変化制約との競合を抑えるための控えめな目的参照であり、25%にすれば禁止区間の可解性が解消するわけではない。
- Centerの座標基底、モデル線形化、操舵予約、Q/R、レーン境界・物理境界・障害物境界は維持する。格納した曲率は幾何検証データであり、操舵指令へ直接代入しない。
- L1/L2、Race復帰、他のsoft参照が所有する向き目標を上書きしない。対象車、Hybrid開始点、進捗、ラッチ、復旧状態は操作しない。
- `_candidate_lane_heading()`もこのL0の位置を使い、追い越し前の姿勢判定で旧中点の向きだけを見ないようにした。

## MPC検証で残った制約

生成経路上の姿勢を初期値にし、WP220〜290の71地点で現行QPを実行した。車両・交通・時系列走行は再現していない。比較の初期姿勢は両方式で同じ。

- 進入禁止区間の外（WP220〜229、256〜290）の45地点は変更前後とも`solved`。
- 禁止区間内では変更前もWP246〜251で`solved inaccurate`／反復上限到達が残る。
- 新参照ではWP245〜251に不正確解、反復上限到達、WP249〜250の`primal infeasible`がある。状態ごとの詳細はJSONに記録した。目的関数変更で制約を変えてはいないため、返却ステータスの違いを新しい物理的幅不足と解釈しない。
- 通過可能な幾何経路を作っても、現行MPCの制約・モデルでそのまま追従可能になるとは限らない。予測点間の曲率入力差に`max_steering_rate * Ts`を使う現在の制約と、空間モデルの近似が次の精査対象になる。単に舵角上限・壁マージンを緩める根拠にはしない。

したがって今回は、WP256以降の突起付近などで利用できる滑らかなL0目標を導入する段階とする。WP230〜255の禁止解除、AWSIMでの無接触通過、移行途中や他車がいる場合の通過までは保証しない。AWSIM走行は未実施。

## 計算時間とテスト

ローカル計測では読み込み約2.8ms、N=15の横位置・向き参照生成は中央値約0.017ms（従来約0.039ms）。計測対象は参照生成部分で、MPC全体の時間や実機周期保証ではない。実行中の追加最適化はなく、参照表を読むだけ。オフライン生成は今回約87秒。

全体テストは **578 passed / 1 failed**。新規36件は通過。失敗は作業前からある`test_outer_course_margin_remains_point_six_metres`で、現在設定0.7mに対しテストが0.6mを期待するもの。マージンを変更して帳尻を合わせてはいない。

新規テストは幾何・車体掃引、読み込み時の不一致拒否、Hybrid/他参照の優先順位、Shadow例外時の本番状態保持、QPのP/A/l/uが変わらずqだけが変わること、WP256〜280の各地点の正確解を確認する。

## ファイルと再現方法

パッケージルート`aichallenge_submit/multi_purpose_mpc_ros`から実行する。

```bash
# オフラインで再生成（走行中には実行しない）
OPENBLAS_NUM_THREADS=1 python scripts/generate_l0_reference.py

# 既存CSVの幾何と車体通過を再検証
OPENBLAS_NUM_THREADS=1 python scripts/generate_l0_reference.py --check
```

生成結果は`env/centerline/l0_reference_wp220_290.csv`と同名JSON。`env`は既存CMakeでpackage shareへインストールされる。生成スクリプトはソースツリーで使う。

ビルド・再起動後に`[PrecomputedL0] loaded objective-only reference: ...`が出れば読み込み済み。`disabled; using original lane reference`の場合は後続の不一致理由を確認する。

従来参照との比較時は`config/config.yaml`の`reference_path.l0_precomputed_reference_csv`を空文字にして再起動する。境界・追い越し判断側を戻す操作は不要。
