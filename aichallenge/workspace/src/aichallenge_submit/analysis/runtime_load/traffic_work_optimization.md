# 交通評価・レーン提案・Shadowの実行整理（2026-09-08）

## 変更範囲

`core/traffic_work.py` とControllerの呼び出し側を変更。
複数台によるレーン順位付け、主対象の選択、既存のレーン適用・Hybrid状態管理は維持。

1. `_vehicle_passage` / `_relative_lane_vehicle_samples` の同一周期・同一入力の結果を共有。
   対象位置・速度・速度有効性、ego姿勢、予測範囲、使用経路、境界値、幅設定等をキーに含める。
   各呼び出し時に境界値を比較するので、同じ周期の本番MPC境界更新後も古い結果を使わない。
   呼び出し元にはdict/listのコピーを返す。周期開始で破棄し、次周期は再評価。
   衝突判定結果やMPCの成功結果はこのキャッシュへ入れない。
2. `_propose_traffic_lane` の将来車両による順位提案を最大0.10秒保持。
   主対象・希望レーン・通過可否・front/side/rear競合・相手ID一覧・速度推定有効性の変化で即再評価。
   安全なactive lane維持はキャッシュ参照より前に実行。
   将来車の位置だけの変化は最大0.10秒遅れて順位へ反映される。
   呼び出し元の地域制限、現在の交通安全判定、Shadow、本番MPC判定は従来どおり。
3. Shadowは用途・候補ごとに同一周期の重複を抑制。
   失敗後は同候補の再試行を最短0.10秒間隔とする（Race復帰にも適用）。
   未確定の成功確認は従来どおり各周期で続ける。
   確認済みの追越し候補の更新は既存freshnessの半分と0.10秒の短い方を間隔にする。
   確認時刻は実際に成功したときのみ更新する。省略で成功数・時刻を進めない。
   committed側へ検証が引継ぎ済みの同対象・同レーンは再試算不要。
   回復中の確認破棄を省略判定より先に行う。候補の変更・リセットで再試行待ちを破棄。

## 動作への影響と限界

評価共有部分は厳密な入力一致。順位提案と失敗Shadowの再試行は最大0.10秒の更新待ちが入り得る。
安全基準の緩和は行っていない。Shadowの第一回試算・未確定の連続成功を遅らせない。
AWSIM未検証のため、走行挙動の完全一致・壁接触解消・40Hz到達は未確認。
成功している未確定Shadowや異なる候補の必要な試算は引き続き実行される。

## 確認

全体テスト600件成功、既存1件失敗の時点から、確認時刻保持と候補リセットの2テストを追加。
`test_traffic_work.py` は8件。通過判定の境界/速度変更、戻り値改変、次周期再計算、
提案の期限/時計巻戻り/現在競合、active lane維持、速度不明化、Shadowの省略/回復/対象切替を確認。
実MPCのShadow隔離テストも成功。
既存失敗: outer_course_marginの実設定0.7mに対してテストが0.6mを要求。今回変更なし。

- `traffic_relative_hits_total`: 前後・レーン位置サンプル再利用回数
