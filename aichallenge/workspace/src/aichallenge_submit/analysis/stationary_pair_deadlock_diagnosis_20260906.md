# 2台停止実験の減速・最終停止の原因

添付ログ3075行と現在controllerを照合。走行コードは変更していない。

## 結論

最後の永久待機はParallelAbortの解除条件が停止車実験に適合していないことが直接原因。それ以前の減速は、横移動の参照上の完了と実車の横位置が一致せず、d2の追越し状態を保ったままd3への緊急制動が速度をゼロへ落とすことによる。空きレーンの発見自体には成功している。

## ログに現れている連鎖

1. 2613〜2617行: d2への厳格Shadowが確認され、L2に確定。開始速度6.88m/s、Hybrid移行距離16.16m。
2. 2636行: 移動距離15.99mでHybridCompleted。距離98%条件であり、実際の横位置到達を意味しない。
3. 2655行: d3を理由に速度上限0.50m/s。縦距離7.77m、車体間隔5.62m、ego_lane=1。
4. 2667行: d3への上限0m/s。縦距離3.35m、車体間隔1.34m。同じ付近のログではL2は通過可・競合なし。
5. 2677行以降: OvertakeTargetLockがactive=d2、candidate=d3を保持。d3は緊急制動では評価されるが追越しの主対象ではない。
6. 2691、2730、2737行: Hybrid完了後もL2中心との横誤差0.82m（進捗監視の到達基準0.45m）。つまり外側参照を用意した距離は走ったが、実車は十分横へ移れていない。
7. 2739行: d2との並走4.1秒でParallelAbortへ移行。d2はL0、yield先はL1、縦差-0.04m、横車体余裕+0.51m。

## A. 最終停止は「Shadowが解けない」だけではない

controller :9239 のParallelAbort解除は、相手が非追跡になるか、Center縦距離がprepass前方判定距離以上になる場合のみ。横余裕が増えた、相手が停止している、別レーンに安全な前進経路がある、といった条件では解除しない。

:9632 のParallelAbort所有権ブロックは、毎周期L1を要求し、_overtake.release_target()を呼ぶ。このメソッドはprobeも破棄する。先に一般選択がL2のShadow候補を準備してProbeHoldを出しても、その後のこのブロックで消える。その後 :11383 のShadow実行へ到達しても、:3935 の対象/レーンなし条件で即returnとなる。

実際、最後の長いProbeHold反復中は、対応するOvertakeCommitProbeの試算結果ログが出ていない。cycles=0/2は「試算して毎回失敗した」という意味に限らず、この所有権による候補破棄でも起きる。

停止したd2に対して「d2が先へ行くまで譲る」を選ぶため、自車もd3で止められ、解除条件が変化しない。これが今回の永久待機の中心。

## B. MPC solvedと前進許可は別

ログ2729行等にはsolvedがある。しかしMPCの後にEmergencyBrakeがref_vel_kmphを0へ下げ、controller :13227 付近でu[0]もその上限へ制限する。また停止中にはゼロ速度参照に対する解が得られることもある。

さらにログ末尾にはprimal infeasibleもあり、最終区間全てで有効解が続いているとは言えない。main/Shadowの素のsolver出力にはインスタンス識別がないため、solvedの各行をすべて空きL2の通過証明と見なしてはいけない。

## C. なぜ無減速で通過せず、先に止まるのか

- :4990付近のHybrid完了はCenter移動距離のみで決まる。横位置誤差・車体分離を伴わないため、「完了」と実車のL1寄りの姿勢が同時に成立する。
- 空きL2判定はそのレーンの通過可能性。現在姿勢からそこへ十分早く横移動できることや、途中の2台を含む車体通過を保証しない。
- 対象d2と実際の制動対象d3が分かれる。d2の確定や通過余裕だけでは、d3への停止を解除しない。
- :12525付近の停止車用速度式は、概ね相手速度 + 1.5×(車体間隔−5.5m)。横方向の安全解除が通らないと、近づいた段階で強く減速する。

前回追加した微速脱出は :3203 で同じアクティブHybrid対象・未完了・横車体余裕0.10m以上を必要とする。最後はHybrid完了済みで、d3との横車体余裕も約-0.05〜0.00m。さらにParallelAbort中は最終微速指令も許可されないため、今回の停止を救えない。

最新外側予測による解除も、横余裕・実際に前進する新しい予測を必要とする。停止後にこれらを満たせない状態を、単にsolvedという理由で解除する設計ではない。

ログにEmergencyBrakeHybridEscapeCreep speed=0.60があることだけで、その周期の全速度が0.60へ制限されたとは判断できない。このログは微速の前進要求であり、通常MPCがより速い前進を出していればそれを上から抑える処理ではない。

## 修正の優先順

1. ParallelAbortを「相手が動いて抜けていく並走」と「停止車群の横で自車が止まった状態」に分ける。後者は、現在車体・他車・移行経路を検証した外側前進へ所有権を渡せるようにする。タイムアウトだけで無条件前進させない。
2. ParallelAbort中に一般選択が候補準備→破棄を繰り返す競合をなくす。待機理由とShadow非実行理由をログに出す。
3. Hybrid参照の完了と、実車の横移動完了を分離する。実車が0.82mずれたまま完了保護や前進手段を失わないようにする。
4. 同じ空きレーンを通る2台を「d2を選択、d3は停止だけ」という扱いから、共通の通過経路として検証する。対象引継ぎ時も安全な同一レーンを維持できる条件を作る。

追加移植済みの微速・最新予測解除は条件付きの出口であり、この上位の所有権競合まで解消したものではなかった。今回の対策は速度余裕の追加より、ParallelAbortとHybrid完了・2台の通過判断の整合を優先すべきである。
