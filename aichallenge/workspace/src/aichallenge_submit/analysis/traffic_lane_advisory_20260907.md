# 対象引継ぎとレーン候補評価の分離

前回の共通レーン実装は、遠方の他車による候補阻害を committed lane hold の
`unrelated_unsafe` に渡していた。今回はこの接続を復活させない。
`_latched_target_passage` と `_evaluate_committed_lane_hold` は従来のままとする。

## レーン候補

`lane_evaluation.py` は不変の評価入力から推奨レーンを返すだけで、controllerや
セッション、参照経路、境界、速度には書き込まない。
主対象の通過幅と近傍の前後左右交通条件を満たした候補を対象とする。
採用済みのレーンがその条件を満たす間は維持する。
未採用の場合は、前方の他車がそのレーンを塞ぐまでの距離が長い候補を優先する。
同点では元の希望レーンを優先する。全車に共通するレーンの存在は必須にしない。

対象以外の全観測車を参照し、前方ラッチ距離内の有効な観測を順位付けへ反映する。
後方・並走車は既存の交通競合判定が扱う。不明な観測はログへ明示し、順位付けから
安全な走行を証明しない。停止位置までの距離・速度計画や全車衝突確認は既存処理が
引き続き担当する。新しい部分経路の走行許可・停止解除は追加していない。

通常選択、対象変更後の候補選択、L1復帰から追い越しへの候補選択に接続した。
地理的な車線制限とShadow確認はその後に適用する。復旧の排他制御は変更しない。
ログは `[TrafficLaneProposal]`。候補なしという結果から直接ライブ状態を解除しない。

## 同じレーンでの主対象引継ぎ

`OvertakeSession.handoff_target()` は同じレーンの継続可能なHybridに限り、
対象識別を更新しつつ同じHybridオブジェクト、開始点、開始時刻、距離、進捗を保持する。
古い対象のprobe、verification、通過余裕確認タイマー、交通履歴は破棄する。
別レーンや完了後の移行にこの継続処理は適用しない。

controllerは、次対象に対して同じレーンの幅・近傍交通・全観測車の現在非重複と
速度観測の有効性を確認する。復旧・ParallelAbortなど別の制御が占有中は適用しない。
同じレーンで引き継げる場合、次対象のShadow待ちでは元の移行を維持する。
新対象のShadowが新鮮であることを確認してから対象識別と検証情報を更新する。
現在の危険条件・停止制約は待機中も無効化しない。

採用時は `_lane_decision` の対象IDも同時更新するため、後段の
`_apply_lane_decision` が対象変更を別の横移動と誤認しない。
境界の移行期限、MPCの初期化状態をリセットしない。
前対象の追従キャッシュとPrepass速度制限は破棄する。
連続追い越し引継ぎにも同じ処理を接続し、既存の停止車群用の継続経路も維持した。
ログは `[SameLaneTargetProbe]` と `[SameLaneTargetHandoff]`。

## 検証

3台が異なるレーンを塞ぐ候補順位、候補なしの読み取り専用性、
d2→d3→d4の対象変更と実際の境界更新メソッドを通した開始点・期限の継続、
Shadow待機、旧速度制限の破棄、別レーン・完了時の継続拒否、
第3車の衝突・速度不明・道路幅喪失・復旧時の引継ぎ拒否を回帰テストに追加。
AWSIMでの安定性と計算時間の確認は未実施。
