対象は現在の `aichallenge_submit`。前段のShadow分離・空間Hybrid実装に、依頼の3〜5を追加した。

## 3. 並走時の選択済みレーン維持

`overtake_lane_hold.py` に継続判定を分離し、controllerの既存ラッチ監視から呼ぶ。対象とレーンをキーにした確認時間を `OvertakeSession` に保持し、検証破棄・Hybrid破棄・対象解除・追越し完了・監視中断で破棄する。

優先順位は次の通り。

1. 車幅を確保できない、対象の形状・距離が不明、車体同士が重なる、他車が危険または情報不足の場合は待機せず既存の全幅回復へ移行する。
2. 対象由来の通過余裕だけが失われた場合は0.40秒連続で確認する。途中で余裕が回復すれば確認をやり直す。
3. 同じ対象・同じレーンの未完了Hybridが35%以上進んでいる、または対象と並走中なら、対象由来の余裕不足だけでは解除しない。既存の区間限定L0追従例外にも1の安全判定を適用する。

現在位置の車体重なりは既存SAT矩形判定で確認する。従来の「対象が前にいる」判定では扱えなかった縦距離ゼロ・少し後方の並走も監視する。既存のL1再進入・Prepass・ParallelAbort等の所有権を優先する条件は維持する。

対象以外の同レーン車は、固定距離のfront/rear分類外も評価する。車体間隔と、追いつく側の相対速度による `目標車間 + 反応時間×相対速度 + 相対速度²/(2×制動減速度)` を比較する。コース方向の符号付き速度を使用し、逆走方向も接近として扱う。予測上の横方向侵入は即時危険。速度推定が無効、位置・車線・縦距離が不明な関連車はunknownとして解除側に含める。区間限定L0だから後方車の情報を無条件に捨てる処理は、この継続監視から除いた。

道路幅評価自体の既存CSV微小ノイズ許容は維持し、非有限の幅は不明として拒否する。その幅判定が失敗した後の0.40秒待機は設けない。レーン解除後の全幅回復・速度制限・緊急制動の既存経路を使用する。

## 4. 遠方での準備と確定

| 項目 | 今回の設定 |
|---|---:|
| 新規ラッチ距離 | 35m |
| 低速車の準備距離 | 35m |
| 通常低速車の確定距離（終盤防御区間も同じ） | 28m |
| 停止車・5.4km/h以下の確定距離 | 35m |
| ラッチ解除距離 | 42m |

既存の距離ゲートは「閾値未満」のため、35m設定では35mを下回ってから新規確定できる。厳格Shadowの鮮度・成功確認は引き続き必須であり、距離の拡大自体は確定許可にならない。追従からの再試行にも速度別の距離を適用する。速度不明なら通常低速車の距離を使う。接近速度の上乗せや地理的な車線選択規則は今回変更していない。

## 5. V2X速度ゼロの短期補間

`zero_velocity_hold_sec: 0.20` と `zero_velocity_threshold: 0.10` をconfig/sim_configのv2xに追加。位置差分による観測速度が0.10m/s以下の場合、最後の有効な移動速度を、その観測時刻から最大0.20秒保持する。ゼロ観測のたびに期限を延長しない。

位置飛び・過大速度・非有限座標・非正の時刻差では移動履歴を破棄し、速度推定を無効にする。snapshotは保持設定と履歴も独立にコピーする。

本当に停止した車でも、保持期間中は従来速度で予測・停止分類される。4m/sから停止するテストでは最後の移動観測が0.10秒、0.299秒まで4m/s、0.301秒の更新で0m/sになることを確認した。期限はV2X観測時刻を基準とし、新しい観測が届かない場合の情報鮮度管理を置き換える機能ではない。
