# 4台同一コース走行のデッドロック候補（2026-09-06）

対象: 現在のaichallenge_submit。自車と他車3台が同一コースを走り、停止・並走・追従が連鎖する場合。各車の実行設定が同一であることは未確認。制御コードは変更せず調査した。

以下の4点は、実コントローラから抽出したメソッドを使う独立した条件再現で確認した。車両配置・経路判定の一部はテスト用入力であり、AWSIMで4台が永久停止することを再現した結果ではない。

## 1. 優先度高: FollowDeadlockEscapeが安全なL2を選べない

`mpc_controller.py:2598` `_select_follow_escape_lane()`。候補にL0/L2を列挙し、通過余裕・車両競合・禁止条件を確認するが、`:2625`で返すのは`selected_lane_idx == 0`だけ。2を許可された場合、そのままループを抜け、L1または候補なしに落ちる。

再現: d2がL1、d3がL0を塞ぎ、L2だけ通過可能。選択結果はNone。L2の競合一覧は空。

4台時の連鎖: d4が後方に追従停止すると後退も拒否され、`FollowDeadlockBlocked`で同じ再評価を繰り返す。空きレーンが存在するため、単に道路が物理的に塞がっている場合とは異なる。

修正方向: 許可された外側レーンをL0/L2とも選択対象とし、既存の禁止条件・幅・交通・前進検証と整合させる。前進許可の検証は維持する。

## 2. 優先度高: ParallelAbort解除が「前方の別停止車」に依存

`mpc_controller.py:3244` `_release_stationary_parallel_abort()`、特に`:3258`。Abort対象が安全な停止車群に入っていても、群に縦距離が正の車が1台以上いないと解除しない。通常解除`:9352`以降は相手が十分前へ進むか追跡から消えることを待つ。

再現: Abort中のd2が横に停止（縦距離0）、d3・d4は後方。L2の停止車群はd2だけで安全候補があるが、20回呼んでもAbortは解除されない。この判定には経過時間による別の出口もない。

発生経路: Abort突入後に並走相手が停止した場合、または以前塞がっていた外側が空いた時点で前方停止車が残っていない場合。最初から停止車群が成立しているなら今回の並走継続でAbort自体を防ぐため、常に発生するわけではない。

前回追加した解除処理の適用範囲不足。前方の次対象がいない場合も、現在の並走対象を基準とした安全な進路再取得へ引き継ぐ必要がある。単に時間切れで走り出す修正は不適切。

## 3. 優先度高: 4台目が停止車群全体を無効にする

`mpc_controller.py:3203` `_stationary_lane_group()`。縦距離-3〜35mの停止車を順に調べ、1台でも候補レーンの通過余裕がなければ`:3232`で群全体を空にする。近いd2・d3を通過してから遠いd4の手前で再判断する区切りはない。

再現: d2（縦0m）・d3（4m）についてL2の群が成立。d4を25m先のL2に停止させ、その車のL2通過を不可とすると群全体が消える。d2/d3を個別に避けられる条件は変えていない。

影響: 群に依存する並走Abort抑止、停止車へのAbort解除、二次対象のHybrid低速脱出、連続追い越しの空間状態保持が同時に使えなくなる。L0も使用不能であれば、近い車への回避途中から停止・再選択へ戻る可能性がある。

これは前回追加した群の定義が4台構成に対して広すぎる問題。d4を無視すべきという意味ではない。通過区間を区切り、d4までの停止可能距離と現在の走行予測を検証した上で、成立している手前の回避を維持する設計が必要。

## 4. 優先度中〜高: 後退距離を後方車までの空きに短縮しない

`mpc_controller.py:2359` `_prepare_follow_deadlock_reverse()`。`:2409`で後退距離を静的壁までの余裕と設定上限6mから決める。`:2417`以降で、その全距離にV2X車両がいればblockedを返す。後方車を基準に距離を縮めて再検証する経路がない。

再現: 静的後退余裕は十分、後方車が3m先にあり6mの後退は不可。短い距離なら後方判定を満たす入力でも、確認は6mの1回だけでblockedになる。

4台時の連鎖: 前方d2/d3に詰まり、後方d4が追従停止すると、わずかに下がって切り直せる可能性があっても長距離後退の不可判定で待ち続ける。FollowDeadlockEscapeは再評価を行うが、同じ配置では同じ結果になる。

修正方向: 静的壁だけでなく、後方車の車体・安全余裕・相対運動を含めた可動距離を求め、短い後退から有効な前進解へ繋がるかを検証する。3m離れた後方車に対して3m下がってよいという意味ではない。

## 優先順と確認範囲

最初に1と2の選択・解除条件を修正し、3の通過区間管理、4の短距離後退へ進めるのが妥当。物理的に全進路が閉塞している状態の安全停止は維持する。

診断スクリプト: `four_vehicle_deadlock_repro_20260906.py`。現在の問題挙動をassertする診断用であり、修正後の合格条件ではない。

実行: `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPYCACHEPREFIX=/tmp/group_cache python -m pytest -q -p no:cacheprovider aichallenge_submit/analysis/four_vehicle_deadlock_repro_20260906.py`

4条件成功。制御コード変更・ROSビルド・AWSIM走行は実施していない。全4台の状態遷移、実際の停止の持続時間、どの車が先に動くかの実証は、配置を固定した複数車両走行ログで別途確認が必要。
